# Workflow

## 是什么

**Workflow** 是一条多步骤流水线。[Agent](./agents) 是单次 Prompt-模型调用,
而 Workflow 把若干步骤按顺序串起来 —— 每一步的输出成为下一步的输入。

## 步骤类型

| 类型 | 作用 |
|---|---|
| `render` | 渲染模板,填充 `{{变量}}`(以及 `{{input}}`) |
| `model` | 用当前文本调用一个模型提供方 |
| `transform` | 做文本变换:`upper`、`lower` 或 `trim` |

`render` 步骤里的特殊变量 `{{input}}` 保存着**上一步的输出** —— 步骤就是
这样串联起来的。

## 为什么重要

真实任务很少只有一次调用。例如:*渲染一个摘要 Prompt → 调用模型 → 去除
首尾空白*。Workflow 把这个序列变成一个保存好、可运行的单元,而不是散落在
应用各处的胶水代码。

## 怎么用

1. 进入 **Workflows** 页面,点击 **新建 Workflow**。
2. 填好 key 和名称。
3. 每个步骤点 **添加步骤**。逐个选择类型并配置:
   - `render` —— 写模板
   - `model` —— 选提供方和模型
   - `transform` —— 选操作
4. 用 ↑ / ↓ 按钮调整步骤顺序。
5. 点击 **保存**,然后填好变量,点击 **运行 Workflow**。

## 看懂运行结果

运行后,结果面板显示:

- **步骤轨迹** —— 每一步的输出,按顺序排列,你能精确看到文本在哪一步变化。
- **最终输出** —— 最后一步的结果。

## 幕后

运行 Workflow 会调用 `POST /api/workflows/:id/run`,返回完整的步骤轨迹。
每次运行都会被记录,供[可观测性](./observability)使用。
